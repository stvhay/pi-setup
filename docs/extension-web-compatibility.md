# Extension web compatibility

This matrix covers the packages configured in `pi/agent/settings.json` and tracked extensions under `pi/agent/extensions/`. Baseline is Pi 0.84.1 RPC hosted by agent-os. Unpinned package sources are intentional rolling inputs and may advance during normal package updates; their exact versions or commits below are observations dated 2026-08-13, not pins or compatibility guarantees.

## Boundary

- Portable `select`, `confirm`, `input`, `editor`, `notify`, `setStatus`, text-array `setWidget`, `setTitle`, and editor-text calls work unchanged after RPC readiness.
- Pi 0.84.1 binds extensions before attaching its RPC stdin reader. Blocking `session_start` prompts therefore cannot consume browser responses. Runtime configuration must be provisioned first or the extension must defer the prompt.
- `archimedes.ts` composes the installed Archimedes public package entrypoint while wrapping only its `ask` and `subagent` registrations. It captures the static ask registration during factory load and decorates the package's lazy subagent registration when `session_start` emits it; extension loading never requires the lazy tool early. The ask wrapper requires `selectionMode: "single" | "multi"` and migrates stored legacy `multi` arguments through `prepareArguments`; TUI/headless calls retain upstream UI/socket behavior while RPC uses portable dialogs. The subagent wrapper preserves upstream execution, validation, rendering, and prompt metadata while adding local single/per-child `outputContract` plus bounded `routingTask`; it strips both fields before upstream execution so parent telemetry can evaluate declared result shape and route class without forking Archimedes. Native parallel output remains visible when no contract is supplied. Explicit contracts normalize that output once: `inline` or an unspecified per-child override projects at most 12,000 total characters in stable child order, complete outputs remain in private delegated artifacts, and non-inline children stay compact.
- `langfuse-config-env.ts` sets the `conversations` preset and unconditionally disables tool I/O, tool-payload byte metadata, system prompts, and cwd before composing the installed `pi-langfuse@1.5.14` public entrypoint. Explicit false input/output flags remain false. Evaluator projection uses the maintained package's public `pi-langfuse/quality` capture port, which owns redaction, observation lifecycle, and buffered/flush delivery; no package-private runtime, redaction, utility import, or parallel sanitizer remains. Two ordered `message_end` handlers expose the zero-priced subscription alias only to upstream telemetry, then restore the runtime model ID for later handlers and persistence.
- `zz-output-redaction.ts` is the shared runtime output boundary. It redacts credential-shaped values from partial/final tool output, tool details, assistant display/final messages, and extension console diagnostics while retaining surrounding status and error evidence. RPC and JSON text/thinking deltas are withheld until complete redacted end/final events are available; user input is unchanged.
- `agent-os-compat.ts` activates only for `--mode rpc`. It supplies `/reload`, text todo/subagent widgets, and the browser-internal `/agent-os-package` adapter. The package adapter accepts only strict `install npm:<name> <approved-version>`, `remove npm:<name>`, or bounded selected `update npm:<name> <approved-version>` pairs after browser approval. It installs approved versions exactly while retaining unpinned project settings, rejects baseline/pinned/non-project updates, reports partial failures, reloads after any success, and skips reload when all selected updates fail. Settings flush and progress cleanup precede terminal `ctx.reload()`.
- `process-restart.ts` is TUI-only. `/restart` and `restart_pi` replace current Node 24 process after graceful shutdown and resume its persisted session by exact file path on macOS/Linux. Optional command input runs through a fixed foreground shell relay from session cwd before exact resume; tool command authority and disclosure match `bash`. Whitespace-only commands, NUL, and exact recovery commands beyond the 1,000-character diagnostic bound reject before shutdown. Shared replacement state permits one pending exit listener and rejects duplicate requests. Process replacement is unavailable in RPC, JSON, and print modes and rejects Windows or missing `process.execve` before shutdown.
- `nvim.ts` is TUI-only. `/nvim` and `nvim` validate zero or one lexical relative path, launch foreground Nvim through shared command relay, and resume exact persisted session after exit. It has same platform, persisted-session, signal, and headless-mode boundary as `process-restart.ts`.
- `bead-handoff.ts` is TUI-only. `handoff_bead` and `/handoff-bead` share source-state/readiness preflight: linked sessions require successful clean closeout, while sessions with zero ownership records may start ready work directly. They select sole ready non-epic work automatically or ask once among several choices, stage one empty parent-linked session, then gracefully replace Pi process and start a bounded Bead kickoff without copying source transcript. Best-effort private records contain only normalized handoff stage, result class, and duration; no Bead/session IDs, paths, payloads, or errors. Nonzero shutdown exit removes staged session; post-exit `execve` failure preserves it and emits bounded target-specific recovery. RPC, JSON, print, ephemeral sessions, Windows, alternate runtimes, and missing `process.execve` reject before shutdown.
- `beads-footer.ts` uses portable keyed `setStatus` only. `agnt work status` carries each item's `issueType` and orders in-progress rows from explicit Beads parent metadata: included parents precede children; roots and siblings sort by priority, stable `created_at`, then natural ID, with missing creation times falling back to ID. ID text never implies a relationship, and `updated_at` is ignored so edits do not reshuffle the footer. It publishes deterministic newline-delimited `◐ ◆ <id>  P<priority>  <title>` rows for Epics and `◐   <id>  P<priority>  <title>` rows otherwise, with a fixed type slot for aligned columns. Warm color remains limited to the status marker, with muted non-session details and bold default current-session details; relevant tool completion refreshes state, and empty or invalid reads clear it. Pi's built-in footer renders the keyed status directly. The version-locked Archimedes footer projection renders each Bead entry on its own sanitized, width-bounded row without collapsing alignment, places exact `caveman` and `ponytail` statuses on the first row whenever they fit or together on one fallback row, and leaves other statuses on dedicated rows. RPC receives the same status update; JSON/print UI methods remain no-ops.
- Ponytail package skills are filtered from automatic discovery while its extension remains enabled. `ponytail-skill-input.ts` handles explicit `/skill:ponytail*` input from users and package aliases, resolves the installed package root from Pi command provenance, and reads the canonical skill body on each invocation. Ponytail still owns aliases, mode state, status, and active-mode prompt injection.
- Arbitrary TUI components, component widgets, custom headers/footers/editors, terminal input listeners, themes, and autocomplete have no exact browser parity. Browser-owned controls replace decorative chrome; unsupported management screens remain unavailable.

## Verification

```bash
scripts/check-pi-config.sh
.venv/bin/python -m pytest tests/test_agent_os_compat.py tests/test_bead_handoff.py tests/test_beads_footer.py tests/test_output_redaction.py
.venv/bin/python -m ruff check pi/agent/bin/agnt_lib tests
.venv/bin/python -m pytest tests/
```

`tests/test_agent_os_compat.py` executes the RPC adapter and Archimedes composition with fake Pi contexts, verifies factory load before lazy subagent availability, session-start registration, strict ask/subagent wrappers, complete upstream subagent definition/result preservation, contract stripping before delegation, legacy question migration, upstream TUI/headless ask delegation, RPC single/multi custom input, and blank-input retry. It also checks `/reload` ordering and package argument rejection, exercises install/remove against Pi's real package manager with a fake npm process, covers text todo rendering and privacy-preserving per-task subagent progress, checks inactivity outside RPC, requires one matrix row per configured package, and rejects TUI-only APIs in tracked extensions. `tests/test_output_redaction.py` uses synthetic-only credential formats to cover tool streams/results, assistant final and headless event output, recursive details, extension diagnostics, and preservation of safe status/error evidence. `tests/test_approvals.py` covers durable selected/custom persistence and approval isolation. `tests/test_pi_packages.py` also proves exact package pins, package skill-only filtering, and explicit Ponytail command expansion from canonical invocation-time bodies. `tests/test_package_patches.py` proves temporary package patches are version-locked, idempotent, checkable without mutation, reject incomplete source state, and exactly match the pinned reviewed fork sources.
