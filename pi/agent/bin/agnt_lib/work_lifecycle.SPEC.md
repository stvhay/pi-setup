# Work lifecycle journal

## Purpose

Preserve unfinished work across session attempts without rewriting outcomes or treating suspension as success. The domain service, CLI, Beads/quality adapters, and Pi continuation adapter are implemented in tracked source. Tests exercise real persistence/Git checkouts, native Beads, SDK loading and a disposable Node host performing actual execve source→worktree→source replacement. The host checks SDK session headers, discovered instructions, built-in read/bash cwd, startup attachment and normal closeout without models. This is not proof of live TUI deployment or any other host.

## Public interface

`LifecycleStore(root)` accepts an explicit private root. The runtime adapter selects `~/.pi/runtime/<canonical-repository-hash>/work-lifecycle`; sibling Git worktrees share ownership state, but retain separate checkout identities. Nested directories within one Git worktree normalize to its physical root; distinct sessions may claim distinct Beads in that same checkout. Git identity and snapshot reads disregard inherited `GIT_*`; mismatched configured roots fail closed.

| Method | Contract |
|---|---|
| `claim(bead, session, checkout)` | Register checkout metadata only, without reading working-file bodies; reject another owner of that Bead, a relabeled session or a reserved relocation target, but allow distinct direct sessions/Beads to share a checkout. |
| `bind_assignment(...)` | Bind immutable execution scope; checkpoint input cannot substitute broader authority. |
| `checkpoint(...)` | Persist structured progress and measured workspace; retain previous checkpoint reference. |
| `prepare(...)` | Validate runtime, target, checkpoint, ownership, isolation, and authority; reserve one deterministic transition and random child ID. |
| `reserve_child_file(id)` | Reserve exact private child path; never allocate a second child on retry. |
| `stage(...)` | Verify both workspaces and yield source ownership after the host stages the child. |
| `request_launch(...)` | Revalidate scope/workspaces; record a single launch request. Repeated calls cannot launch again. |
| `attach(...)` | Revalidate scope/workspaces, record attaching, claim/link through host callbacks, and settle ownership. |
| `status` / `recover` / `pending_transition` / `child_transition` | Read exact reservation and recovery action; never launch. |
| `cancel(...)` | Restore source/prior target before attachment. Launch-requested cancellation requires a known pre-exec host failure, not a timeout. |
| `release_terminal(...)` | End a verified closeout's execution. The same `completed` phase is also set by guarded terminal-departure attachment; it does not imply success. Ordinary suspension remains `paused`. |

### CLI and Pi adapters

- `agnt work checkpoint <bead> [--input-file progress.json|-]` preserves unfinished work or verified terminal-departure context. JSON is bounded to 64 KiB; `-` uses stdin. Curated progress may omit `assignmentRef`, which is filled from immutable execution ownership; an explicit different scope is rejected. Without supplied progress, it retains prior curated progress; for a first checkpoint it records canonical objective and measured state without inventing completed work or verification.
- `transition-context --session-id ID` distinguishes unassigned, continuable, successful-but-unclosed, closed-success, terminal non-success and insufficient legacy ownership, retaining pending source or reserved child identity. Terminal classification alone does not authorize release.
- `transition-check [bead] --mode resume|switch|next --session-id ID [--checkpoint-ref ID] [--checkout PATH]` returns a read-only readiness/idle manifest.
- `transition-prepare` accepts the same arguments plus `--runtime-ready`; it reserves only after validated readiness. Missing cross-Bead checkouts produce an `isolating` reservation before any delivery receipt or native write.
- `transition-bind-child <id> --session-id ID` repairs a crash between reservation and child-path binding. It verifies current source session/file/checkout and rechecks ownership under lock, binds only the existing child's deterministic private path, and creates no file, receipt, child identity, or native effect. Explicit-null prepared/isolating paths are recoverable; missing/invalid fields and post-staging unbound paths fail closed. This bounded metadata repair remains available for cancellation after revocation.
- `transition-isolate <id> --session-id ID` recovers the same native worktree receipt, observes its current identity, and binds the resulting checkout before staging. Revocation permits reconciliation reads, not advancement.
- `transition-stage`, `transition-launch`, `transition-attach`, and `transition-cancel` take transition ID and `--session-id`.
- `transition-status` / `transition-recover` take the exact transition ID. Recovery also returns the referenced checkpoint, so a fresh child can retrieve actual progress rather than an opaque ID. Optional `transition-recover --compact` replaces only workspace `changed` inventories with counts and fingerprints, preserving all progress, identity, state, uncertainty and recovery actions (including null unresolved target workspaces). The default command retrieves full inventories; storage and lifecycle validation are unchanged.
- `direct-start --compact` omits expanded dependency/dependent description/design/notes/acceptance prose and metadata from returned Bead data. Current task fields and all other dependency fields remain intact; claim/link validation and failure statuses are identical. Both compact responses identify full-detail retrieval and warn that presentation is not authority. Referenced decisions require full inspection before effects, including rejected/pending decisions, revocations and consumed grants; closed dependency status alone is not approval. No text is truncated to meet a byte budget.
- `transition-abort-launch` is a host failure callback with a bounded `--reason`. After launch reservation it requires the same opaque capability supplied over a private pipe at `transition-launch`; a reason/session/transition flag alone cannot cancel an uncertain launch. It is not user approval or a model-facing failure assertion.

`handoff_bead` supports `mode`, `targetBead`, `progress`, `checkpointRef`, `checkout`, and `transitionId`. `progress` is the current concise objective, decisions, completed work, next steps, blockers, verification, owned relative paths and artifact refs; the host sends it over stdin in the same handoff call. It is evidence/context, never authority. New progress cannot accompany a checkpoint selector or pending/exact transition recovery. Headless calls return it in their read-only manifest without checkpointing. Unfinished assigned work defaults to resume, or switch when a different target is supplied. Terminal non-success sources default to `next` through reserved continuation; successful-closeout/unassigned ready-work handoff remains separate. Tool and slash command select by inspected source state, not incidental option presence. Progress/checkpoint/checkout/mode options on unassigned or closed-success sources are rejected before writes, rather than silently discarded. `/handoff-bead resume|switch|next [bead]` and `/handoff-bead recover <transition-id>` use the same adapter. Headless continuation returns a host-required manifest without checkpoint, reservation, cancellation settlement, or shutdown. Existing reservations recover their recorded mode; explicitly changed mode/target/checkpoint/checkout conflicts rather than silently launching old intent. TUI recovery advances native isolation once through its existing receipt, or finishes an already recorded cancellation. Blocked/uncertain effects never stage a child. A known exit-2 blocked response reports its actual reservation state. Rejection before reservation and an unknown requested ID remain blocked without inventing uncertain effects; an existing reservation requires exact recovery. An unreadable journal reports unknown inspection state, never absence. Other command/transport failures remain errors. Responses without fresh transition state label earlier state as last-observed. Slash commands display non-launch outcomes instead of silently discarding them.

Preparation validates the persisted source header and records its canonical path plus `sourceQualityDirectory`. Source outcome checks use that immutable ledger binding, not the child's checkout-dependent default. Global fallback and ignored project-local quality stores both remain supported without migration or rewriting parent rows. Missing legacy bindings require reconciliation, not a guessed child-local ledger. Existing target checkouts also inspect their own local legacy attempt ledger before reservation. The Pi adapter stages a fresh SDK session header with reserved child ID and exact parent linkage, fsyncs it, records launch intent, and requests process replacement. Stage and attach reject mismatched parent linkage. Host checks immutable reservation identity after isolation, staging, and launch responses. Crash recovery permits only validated null-to-bound child-path repair through `transition-bind-child`; every other identity field must remain unchanged. It never copies source messages. Replacement reconstructs run options through Pi's public argument parser: tool exclusions, project/context restrictions, model/provider settings and explicit resource paths survive; old messages, attachments and session selectors do not. Cross-checkout continuation with custom prompt overrides, Node launch options (including NODE_OPTIONS) or unknown extension flags stops before staging/shutdown instead of guessing how relative options rebind. The reservation remains recoverable; normal launches without those options can switch. On child startup, canonical attachment completes before tools are allowed. Failure blocks tools and requests shutdown. Reserved-child kickoff runs compact direct-start/recovery separately, replacing duplicate full Bead display and eager artifact reload with checkpoint-first, next-step retrieval. It still requires current canonical decisions/restrictions before effects and recovery of incomplete output. Freeform task notes and checkpoint decisions/blockers are never abbreviated; large required facts may exceed the illustrative context target. Source history/outcomes remain untouched. Claimed-target attachment uses native idempotent Beads claim and immutable quality-session linkage.

## Authority and ownership

Direct starts reserve ownership before external claim/link. This is not an exclusive checkout lock: separate tasks/sessions can share a checkout, but must coordinate overlapping edits and the shared Git index. One task per session and one session per task remain enforced. Clean tracked-tree closeout remains required, so another task's uncommitted tracked changes can delay closeout; never commit unrelated changes to clear that gate. Same-Bead resume in its existing shared direct checkout does not let unrelated owners veto continuation. Cross-Bead switches and relocation destinations still reject other unfinished owners; completed records remain intact. A terminal source may use the same clean checkout for its next assigned task; unfinished cross-Bead switching still requires isolation. Readiness and preparation use the same ownership, mode, workspace and loop checks; preparation reruns them under the journal lock. Readiness reserves nothing. Transition isolation and snapshot checks remain unchanged. Under standing authority, a requested Beads claim requires `beads-write`; continuation requires both `work-transition` and `beads-write`. Initial denial occurs before ownership reservation, claim, or quality link. The captured scope is rechecked inside the quality transaction immediately before native claim, including child attachment, so queued revocation cannot pass through stale preflight. This recheck never reacquires lifecycle ownership. Legacy inactive-policy behavior remains separate; authority denial is not misreported as session ownership conflict. With active standing admission, selected work lazily reuses its private assignment or records a local-only single-Bead scope. First `direct-start` may add repeatable `--scope-bead` for an explicitly approved work set; canonical selected Beads must exist and be unfinished. One immutable assignment covers exactly that set, including local worktree creation for multiple Beads. No authority JSON is needed. Overlapping, narrower or different existing scopes fail rather than merge/widen; an exactly matching existing assignment retains its effects/exclusions. Scope capture is not authentication of arbitrary CLI assertions: the caller must have actual user-assigned intent. It does not infer a delivery objective or scan/enroll other projects. Conflicting assignments require intent resolution. Without admission, legacy direct scope permits only same-Bead continuation. Revocation prevents new continuation attempts; a checkpoint cannot downgrade standing scope to legacy scope.

Same-Bead relocation may target an existing checkout in the same canonical repository under captured authority. The transition reserves its destination against competing claims/transitions without changing the source owner binding. Attachment alone updates the checkout; cancellation restores the source phase. Source/target drift, wrong headers, foreign repositories and revoked scope remain blocked. Source dirt is neither copied nor integrated. Fixture round trips do not establish live-host launch capability.

Terminal departure requires a retained `partial`, `failure` or `unclear` source outcome, canonical `closed` status with nonempty `closed_at` and `close_reason`, the existing active execution owner, matching persisted source header/checkout, no pending transition and no unresolved admitted delivery receipt for its assignment/Bead. Missing or unreadable evidence blocks rather than guesses. Source closure alone cannot claim/release a missing owner. The existing checkpoint/reservation/attachment flow retains exact recovery; successful child attachment alone ends source execution as `completed`, without replacing its immutable outcome. Cancellation retains the active source; uncertain launch/attachment retains its reservation. Target must be in captured scope and a clean existing checkout of the same canonical repository; native creation is not available for terminal departure. Source dirt remains untouched. Single-Bead legacy scope grants no next Bead; resolve actual assignment rather than inferring authority from completion. Success/partial-closeout repair remains separate. Reopened sources must again satisfy unfinished isolation at staging, launch, and attachment, using immutable checkpoint checkout facts supplied to authorization without changing journal schema.

Claim raises the existing typed ownership conflict only for ownership conditions. Its public reason distinguishes foreign Bead owner, checkout mismatch, inactive owner, linked/finalized session, legacy ambiguity and reserved destination; private exception details are not echoed. Storage and validation failures remain their original non-ownership exception types; direct-start reports `storage-failed`, `validation-failed` or `operation-failed` without private exception text. No `/new` takeover prescription is attached to direct-start conflicts.

Direct closeout validates the target Bead's recorded session, checkout and phase, not exclusive ownership of the whole checkout. Other Beads' owners remain unchanged and do not block a matching recorded owner, including completed-owner retries. An unowned legacy attempt still fails when another unfinished owner occupies the checkout. After updating the helper, retry blocked closeout in the original owning session; no journal cleanup, takeover or manual Beads closure is needed for this conflict. Dirty tracked changes, pending transitions, mismatched session headers and authority failures still require their own resolution.

Direct closeout reuses the execution owner's captured assignment; it never enrolls or widens scope. Active standing admission without a captured assignment fails closed. Before success recording it checks the `beads-write` and `repo-write` ceiling (plus `git-commit` in shared mode), current execution context, canonical dependencies/decisions, and any existing close reason. Native close, export/replacement, staging, and commit recheck their remaining effects and target identity. A redirected/nonregular portable target or detected parent change stops advancement. Portable export opens a verified no-follow parent descriptor, creates an exclusive temporary file relative to it, sends native exporter stdout to the open file, and uses descriptor-relative replacement/cleanup. Namespace changes cannot redirect those operations to a different directory. An in-flight operation can still affect its originally bound objects if an external actor moves them; subsequent drift prevents staging. Later denial preserves already-recorded outcomes, canonical close, and staged changes; `repair.safeToRetry=false` directs authority reconciliation rather than automatic replay. Legacy inactive-policy direct permission remains separate. Native close/export/stage/commit failures report exit status and fixed safe hints for children/deferred work, signing, locks or filesystem permission; unknown text is withheld with a local-inspection hint. No raw stderr, titles, paths or credentials are returned. A committed source whose checkout becomes dirty later is diagnosed as already committed with newer changes, while the clean-tree gate remains closed. These guards do not yet provide receipt-backed reconciliation for ambiguous native close/export/commit outcomes.

Beads publication is independent of code Git authority. A tracked `.beads/issues.jsonl` selects shared export/parity/commit; ignore rules do not silently downgrade a tracked export. Without it, local-only requires no tracked `.beads` paths and an explicitly ignored `.beads/` directory. Mixed/ambiguous tracking fails before success recording. Local-only validates canonical ID, closed status, nonempty closure timestamp and exact reason, skips export/parity/stage/commit with reason `local-only`, and returns `commit: null`. Optional exports are not evidence. Closeout and successful handoff share mode selection and the clean tracked-code gate. Successful handoff also requires any recorded owner to match the source session/checkout and be completed; canonical closure alone cannot bypass failed finalization. Unowned legacy attempts retain their existing compatibility path. Rechecking mode and directory identity stops drift without migration or publication. Local-only linked worktrees need no checkout-local `.beads/`; native common-directory discovery remains authoritative. Native ignored bookkeeping is allowed; Git clones omit it, and ignoring does not erase previously published history. Dolt backup/remote changes remain outside closeout authority.

Orchestrated controller claim/close checks native bookkeeping authority separately from worker effects. Standing invocation snapshots are revalidated before bundle creation and again around native claim; close revalidates the stored snapshot. Read-only or exact-grant worker actions cannot bypass controller checks: existing captured/unique scope is used without enrollment, with `beads-write` required under standing policy. Inactive-policy ordinary legacy bookkeeping remains a separate compatibility contract, not authority derived from an exact worker grant. Every path rereads canonical constraints. Known owners must match current session, active phase and captured assignment; lifecycle lock spans checks and native callback. Exact worker gates are re-resolved and checked for local revocation before final controller checks; missing expected implementation snapshots fail closed. Canonical exact `targetBead` must match the actual dispatch/invocation Bead at admission, worker dispatch and native revalidation. New envelopes retain this target; legacy envelopes without the field require a fresh matching canonical target and are not rewritten. These checks neither widen worker grants nor renew/consume experiment claims. This does not reserve/transfer orchestration worker sessions, create epic worktrees, or reconcile uncertain native effects.

Canonical Bead status/dependencies and decision constraints are reread at preparation, staging, launch, and attachment. Targets must be open/in-progress and unblocked. Cross-Bead switches use an existing isolated checkout or the native worktree delivery adapter. Readiness reports `needs-isolation` without writes. Preparation reserves execution ownership and immutable action intent before preparing a receipt; a crash between receipt creation and binding reuses that same receipt. Receipt publication and binding share the lifecycle lock with cancellation, so cancellation cannot release ownership while an unpublished receipt is still being created. Existing ambiguous/native-partial state never permits blind creation or adoption. Automatic `next` uses deterministic ordering among eligible assigned ready items. No eligible target returns bounded idle state.

Lock order: lifecycle → quality → authority → Beads. Authorization checks do not retain the authority lock while entering quality. Host callbacks must not reacquire the lifecycle lock. Isolation publication/settlement may enter delivery under lifecycle; native delivery adapters must not acquire lifecycle in the reverse direction. Success recording holds lifecycle before quality. Current canonical and transition-bound source ledgers exclude pending reservations, including explicit source-directory writes from a sibling checkout; unrelated telemetry directories do not finalize execution. Transition authorization rereads source outcome under lifecycle; a successful source must repair closeout rather than start an unfinished continuation. Attachment's nested quality callback rechecks external authority without reacquiring quality: lifecycle already protects the preceding outcome check. Process death releases the OS lock, not semantic ownership. Elapsed lease time never proves execution ownership is available. Existing ambiguous legacy attempts require reconciliation rather than implicit takeover.

## Persistence and recovery

`journal.json` contains `{state, fingerprint}`; state schema 1 contains `owners`, `checkpoints`, and `transitions`. Files are mode 0600 under an owner-private mode-0700 directory, with symlink rejection, bounded payloads, advisory locking, fsync, atomic replacement, and directory fsync. Fingerprints detect accidental inconsistency, not hostile same-user rewriting.

```text
isolating → prepared → staged → launch-requested → attaching → attached
isolating/prepared/staged → cancelled after safe settlement
launch-requested → cancelled only on proven pre-exec failure
```

Isolation cancellation durably records `cancelRequested` before settling the bound or recoverable unbound receipt. A crash after delivery cancellation but before lifecycle settlement reports `finish-cancellation`; it cannot restart preparation or launch. Advancing workers reread cancellation state after native completion. Prepared/definitely unapplied effects can be cancelled; applied effects require a fresh exact observation. Unknown or busy writers retain the target reservation. Cancellation never deletes created worktrees, branches, or dirty data. Direct closeout and completed-ownership release reject pending transitions. Closeout validates current checkout/session ownership and read-only Git preflight before recording success; inherited Git redirects cannot change the commit repository. Legacy headless callers retain their explicit session/checkout contract.

A trusted headless host may attach an already staged child directly. The TUI adapter always records launch intent first. A source retry discovers the existing pending transition rather than creating another checkpoint/child. Unknown launch outcome returns reconciliation-required. An attaching record requires an independent boolean inspector: linked, definitely unlinked, or unresolved. Only definitely unlinked permits retry of the same idempotent claim/link, with a maximum of three attachment attempts.

Lost launch acknowledgement before shutdown uses `launch-request-failed` compensation with the same private capability, never an unproven public assertion. Synchronous shutdown-request failure removes the replacement listener and compensates source/target reservations. Nonzero shutdown and thrown exec calls use a bounded synchronous compensation callback, because exit handlers cannot await promises. Failed compensation retains uncertainty and recovery references. The Pi host generates a 256-bit per-launch secret, holds it only in its closure, and passes it through private IPC. The journal stores only its scope-bound hash; no tool parameter/result or command-line argument contains the secret. Ordinary CLI callers cannot manufacture an existing host's compensation proof. This protects the supported interface, not arbitrary same-user code or private-state rewriting. Child files remain evidence; cancellation never deletes or overwrites them.

A maximum of three completed transitions with identical source/target, measured workspaces, and recorded progress prevents unchanged-state continuation loops. Changed measured or recorded progress allows further work; this is a loop diagnostic, not verification evidence or an arbitrary task-size limit.

Snapshots record HEAD, branch, logical index/status fingerprints, and changed/untracked path hashes, not bodies. Material tracked files hidden by index flags remain measured; index-only changes cannot evade staging checks. Symlinks are not followed. Limits: 4,000 paths and 64 MiB per changed file. Ignored runtime data is not copied. `ownedPaths` never authorizes deletion or auto-commit. Prior verification strings are historical checkpoint facts, not fresh release-gate evidence.

## Invariants and failure modes

| ID | Contract | Enforcement |
|---|---|---|
| INV-1 | Same-Bead continuation preserves outcome/history and one child identity | Immutable quality rows; deterministic reservation and child ID |
| INV-2 | A→B→A preserves isolated dirty work | Paused ownership and source/target snapshots |
| INV-3 | Uncertain launch/attachment is not blindly replayed | Single launch request; independent attachment inspector |
| INV-4 | Known pre-exec failure leaves source resumable | Recorded bounded compensation; no child deletion |
| INV-5 | A recorded owner can resume and close its Bead in a shared direct checkout without changing other owners | Shared transition facts and per-Bead closeout checks; two-session regressions |
| INV-6 | Claim does not inspect working-file contents | Metadata-only checkout identity; unborn/large/ignored/gitlink regression |
| INV-7 | Same-Bead relocation preserves source binding until attachment and reserves one destination | Existing transition and checkpoint records; round-trip, collision, drift and cancellation tests |
| INV-8 | Terminal departure ends only its owned execution, retaining non-success outcomes, admitted effects and source files | Closure evidence, receipt/ownership/scope guards, clean destination, reopened-source isolation revalidation; terminal-departure tests |
| INV-9 | Shared and local-only Beads both support verified closeout/handoff without changing publication choice | Common mode resolver, mode-specific closure proof, authority/ownership checks; local and native stealth/worktree regressions |
| FAIL-1 | Foreign owner of the same Bead, relabeled session, or ambiguous legacy owner | Reject; never steal by actor or elapsed time |
| FAIL-2 | Changed snapshot or revoked/invalid scope | Stop before attachment; preserve files/journal |
| FAIL-3 | Closed/deferred/blocked target | Reject without reopening |
| FAIL-4 | Unsupported launch runtime | Host-required manifest or refusal before yield |
| FAIL-5 | Wrong reserved child header, file, session, or checkout | Reject attachment |
| FAIL-6 | Ambiguous/mixed Beads tracking or mode drift during closeout | Fail before mutation or preserve partial state; never auto-publish/untrack |

- `work.py`: canonical Beads access, deterministic ordering, direct closeout.
